# P7.3 two-host complete37 performance-only gate

## Objective

Add a manually invoked, source-frozen performance gate for the PyPy runtime
candidate. It must execute the original D15 selected128 path for exactly 37
rounds on two independent hosted jobs: Host 1 with CPython 3.12 and Host 2
with PyPy 3.11. Both jobs start from the same seed-0 genesis and source
commit; the summary job compares every round before declaring a candidate
PASS. This gate never runs seed16384 or seed49152 and never changes the
production/default interpreter.

## Fixed contract

- source checkout: `65e1d78576026b0214a0184bd6028e01dc3cc7e1`
- performance seed: `0`
- rounds: exactly `37`, each with original default1024 / native selected128 / 4 workers
- host roles: `host1_cpython` and `host2_pypy`, one runtime per independent hosted job
- runtime identity: CPython 3.12 and PyPy 3.11, attested before and during work
- each round: selected-v7 digest, D15 base/8-batch/final payload hashes, read-only observer hash
- report provenance: host/platform/CPU identity, interpreter identity, run metadata, and pinned PyPy archive URL/SHA
- hard limits: 1080 seconds per host, 180 seconds per round, 1536 MiB sampled RSS, 128 MiB journal, 512 MiB retained scratch
- any source/seed/runtime/parity/resource failure: `INCOMPLETE` or `REJECT`, never a pass
- pass classification: all 37 rounds match and both full-run speed/resource gates pass; still candidate-only

## Rulings

- P7.3 uses two independent full37 runtime replays rather than a D16-style
  20+17 handoff. This keeps both runtime reports independently source-bound
  and makes per-round parity auditable; the cost is two complete seed-0
  performance replays.
